# Nodelace goal and reference comparison — 2026-11-06

Nodelace achieves the core architectural goal: an agent can write a short semantic description and let local Python produce all layout and SVG. It does not yet replace Diagram Design's visual vocabulary or editorial judgment. Keep this approach; prioritize correctness and a compact agent interface before adding many types.

**Scope and evidence.** Reviewed all Python implementation modules, tests, documentation, packaging, workflows, ten examples, and repository history. Local revision: `c727ec6` (0.1.0; August 14). Reference: [Diagram Design 2.6.142, e57eda6](https://github.com/cathrynlavery/diagram-design/tree/e57eda6102a19444538ebd611d39534fad65b663), fetched November 6, including history since August. The local repository does not record an upstream baseline, so this is a comparison with current upstream, not a proven diff from the exact version originally used.

Validation on Windows/Python 3.12: 138 tests passed, 6 platform-specific skips, 93% combined statement/branch coverage, Ruff passed. Built a wheel and imported/rendered from it in isolated Python, including bundled fonts. Initial test collection required `PYTHONPATH=src` because the package was not installed in this interpreter; that was environment setup, not a product failure. Full `python -m build`/Twine and other OS/Python combinations were not run. Browser probes used Chromium, waited for fonts, and inspected screenshots. Reference screenshots were inspected in offline fallback-font mode; precise token comparisons came from source, not those screenshots.

**Does it save tokens? Yes, with an important measurement boundary.**

Measured all ten existing examples using `tiktoken`'s `cl100k_base` encoding:

| Representation | Total tokens | Range per example |
|---|---:|---:|
| Existing `.diagram` inputs | 655 | 22–85 |
| Corresponding generated SVG, fonts excluded | 20,503 | 1,136–2,443 |

The input is **96.81% smaller** than its corresponding output. This is a representation-size comparison, not a measured reduction in total LLM billing and not an equal-quality comparison against an upstream agent run. Actual savings depend on prompt overhead, cached input, model tokenizer, tool messages, corrections, screenshots, and reasoning. No paid LLM benchmark was run.

The current upstream `SKILL.md` alone is 7,441 tokens with this tokenizer. Adding its style guide, architecture reference, and layout-budget reference gives 16,969 tokens if all four are loaded in full. These are file sizes, not a claim that every upstream request loads them all or pays uncached rates. Upstream already uses templates, routed references, and Python helpers.

Warm in-process medians over 25 renders per example were 0.58–1.39 ms with default font embedding. These exclude interpreter startup, file I/O, browser display, and LLM time. Each embedded SVG is approximately 275–279 KB: mostly font data and notices, not agent-generated content. Keep this output on disk; sending it back into the model would squander the savings. The CLI already returns just a path.

Raw measurements: [metrics.json](audit-2026-11-06/metrics.json). For an honest future end-to-end benchmark, use the same briefs and required semantic features in both workflows; record input/output/reasoning tokens where exposed, retries, latency, and visual acceptance. Include cases both systems can represent and report unsupported cases separately. Do not compare a plain three-box graph with a fully annotated editorial illustration and call the difference efficiency.

**What is already working well.**

- The core has no runtime dependencies, model calls, or network clients. Font embedding preserves offline editorial typography.
- Parsing, immutable semantic model, geometry, and serialization are separate. This is a suitable foundation for extending visual rules without asking an LLM to place coordinates.
- Source-aware errors, quoting, Unicode handling, input limits, XML escaping, safe theme values, and protected file publication are implemented and tested.
- Deterministic ordering and byte-checked example SVGs give reproducibility. SVG title/description metadata and selectable text are present.
- CI declares Windows/macOS/Linux and Python 3.11–3.14 coverage. This audit verifies only the local run, not current hosted CI status.

**Confirmed problems, in priority order.**

1. **Text measurement can produce visibly broken output with valid input.** `layout/layered.py:59` estimates node width as `len(label) * 8 + 32`; `renderer.py:127` wraps by character count rather than glyph advance. Thirty `W` characters render about 407.8px wide in a 272px box. Thirty Han characters measured 422px in the same width. The Latin case also extends beyond the left canvas edge. This is not only an unsupported-font issue. See [wide-label.png](audit-2026-11-06/wide-label.png). Use shared, deterministic font-width metrics and wrapping for sizing and rendering; precomputed bundled-font advances can avoid a runtime dependency. Treat wide/full-width Unicode and combining marks explicitly and document fallback uncertainty. Retain full source labels when clipping is necessary, and emit a diagnostic rather than silently concealing important wording.

2. **Outer routing does not avoid all intervening nodes.** `layout/router.py:131` selects channels from ranks and outer bounds, without obstacle checks for every route segment. This five-node, eight-edge input routes `E -> D` through `F`, making a direct relationship look as if it passes through F. See [routing-obstruction.png](audit-2026-11-06/routing-obstruction.png):

   ```text
   architecture "Routing probe"
   E -> A
   A -> E
   A -> B
   E -> D
   B -> E
   B -> D
   E -> F
   A -> F
   ```

   Check segments against non-endpoint node rectangles, then select clear ports/doglegs. Shared-rank ordering has no crossing-reduction pass. A four-node example (`A -> C`, `B -> D`, `A -> D`, `B -> C`) also produces ambiguous crossings without bridge marks: [crossing.png](audit-2026-11-06/crossing.png). Improve deterministic ordering and route validation before replacing the whole layout engine.

3. **Multiple inline SVGs can interfere.** Theme CSS uses global selectors such as `.canvas`, `.title`, and `.node-box`; SVG `<style>` is not an isolation boundary in HTML. In a page containing a light SVG followed by a custom black-background SVG, both backgrounds became black. `_fingerprint` also excludes theme and instance identity, so two copies of the same semantic diagram duplicate title, description, and marker IDs. Scope selectors to each SVG and accept a deterministic caller-supplied instance prefix. Including theme in the hash alone does not solve repeated identical diagrams. Standalone SVG files and separate `<img>` documents do not have this shared-document problem. Probe result: [extra.json](audit-2026-11-06/extra.json).

4. **Syntax success is not publication readiness.** `cli.py:70` only parses for `check`; it never runs layout or visual checks. The existing layout tests assert selected fixtures, and example snapshots preserve bytes, not a comprehensive quality contract. Add an optional layout check for text overflow, connector/node intersections, overlapping labels, focus count, and display-size budgets. Keep browser screenshot/font checks in development or an optional export tool, preserving the dependency-free runtime.

5. **Contrast checks cover too few roles.** `tests/test_theme.py:91` checks ink/muted text but not highlight outlines or lifelines. Measured against Nodelace paper: accent 2.22:1, hairline 1.49:1. The reference now requires 3:1 for essential non-text marks and 4.5:1 for normal text; evaluate each role against its actual background. Nodelace's FOCUS text provides another emphasis cue, so this is not a claim that the whole output fails accessibility. Lifelines and essential outlines deserve role-specific tests.

6. **Dense output can be technically valid but unusable at its destination.** A 50-node star produced a 1,960 × 5,568 layout, with the hub itself 1,568px tall. The renderer warns only above 20 nodes or 40 edges; the reference generally budgets 9 nodes, 12 relationships, and 1–2 focal elements. HTML scales SVG down via `max-width:100%`, without a minimum readable width/local scroller. Add a target-size/readability budget and a warning recommending an overview/detail split. Preserve the current hard resource ceilings as separate safety limits.

Nodelace has the recognizable font combination and restrained composition. It is not a faithful implementation of the current style. In particular, matching colors would not recover semantic shapes, message types, annotations, or the deliberate selection of what to omit. Architecture and flow currently share the same rectangle renderer. The model cannot express several distinctions the upstream examples communicate.

**Can Python emulate 100% of the style?**

- **A fixed template or defined visual contract: yes.** SVG, CSS, fonts, semantic colors, shapes, markers, spacing, annotations, and wrappers are programmable. Use the same assets and a pinned rendering environment for pixel-level fixture comparisons. Arbitrary browsers/fonts/DPI will not give universal pixel identity.
- **All 45 families: technically implementable, not present today.** They require distinct data models and layout rules. A single boxes-and-arrows graph cannot faithfully represent a chart, floor plan, service blueprint, or editorial comparison.
- **The same editorial decisions an LLM might make for arbitrary prose: no guaranteed 100% equivalence.** Choosing the right story, diagram family, focal point, terminology, and omissions is an underdetermined interpretation task. The reference itself allows model-dependent layouts. There is no single canonical output to reproduce for every prompt.

Use a hybrid: the LLM determines meaning and writes a concise specification; Python enforces visual rules, computes geometry, and renders. Keep limited semantic hints such as order, role, grouping, and focus available for difficult compositions. Return compact diagnostics to the model rather than the SVG payload. This retains most of the token advantage while making presentation deterministic.

**Recommended next release, ordered by value.**

1. Fix width/wrapping, obstacle routing, and inline isolation. Add regression fixtures from this audit and development-only rendered-bounds checks.
2. Ship a concise agent quick reference: supported syntax, one example, the render command, limits, and explicit instructions to return file paths rather than generated SVG/font data. A target of a few hundred tokens is reasonable; benchmark it rather than loading the full README each time. No MCP server or model API is needed.
3. Add a pinned reference-compatible preset: current palette, typography/strokes, 1–2-focus guidance, and useful density diagnostics. Expose presets in the CLI. Move to new defaults deliberately because output bytes are part of the versioned contract.
4. Enrich the existing three families before adding more: explicit node roles and flow shapes; edge roles; sequence returns/async and simple fragments; tags/sublabels and a real legend. Extend the compact language only where semantics require it.
5. Add optional destination sizes, dark theme, and a separate PNG export extra when needed. Browser/raster dependencies need not enter the core.
6. Add only frequently requested new families. A lightweight TOML brand profile can use Python 3.11's standard library. Defer website scraping, animation, GUI editing, broad import support, and full upstream parity until actual usage warrants their complexity.

Maintain a small upstream-reference manifest with the pinned revision, chosen supported contracts, and visual regression fixtures. Update intentionally. This audit changed no implementation code; the report and evidence are the deliverables.
